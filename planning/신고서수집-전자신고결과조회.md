# 홈택스 신고서 원본 수집 — 전자신고결과조회 자동화 구조와 함정 (v4.20 완결)

> 2026-07-08 종합소득세 신고서 수집 완결(김태호 실측: 복식부기 9/34/15쪽 전체 페이지 성공).
> 같은 경로를 쓰는 **양도소득세·증여세·부가가치세·법인세 신고서**로 확장할 때 이 문서를 먼저 읽을 것.
> 관련 파일: `chrome-extension/content-hometax.js`(collect_tax_return 모드), `chrome-extension/background.js`(print-pdf), `chrome-extension/suppress-alert.js`, `lib/doc-types.ts`(기본 기간)

## 1. 전체 흐름 (v4.20 기준)

```
앱 자료수집 화면 → #savetax= 해시로 홈택스 열기 (mode: collect_tax_return, returnType)
→ 로그인(+주민번호) → 전자신고결과조회 메뉴 진입
→ 세목 select 옵션 로드까지 폴링(최대 60초) 후 세목 선택   ← 실패 시 수집 중단(empty 오보고 금지)
→ 기간단위 '1년' 클릭 → 조회기간을 달력연도 단위로 분할(buildYearWindows)
→ 연도별: 날짜 입력(검증+재시도) → 등록번호 입력 → [조회 전 그리드 서명 저장] → 조회 클릭
  → 그리드 서명이 "달라질 때까지" 폴링(최대 27초)                ← 스테일 그리드 오인 방지
→ 접수번호 링크 클릭 → 신고서보기 팝업(UTERNAAZ34) 열림
  [팝업 스크립트]
  → 초기 뷰어 프레임 로드 확인(viewer-ready-count)
  → ★ 신고서 목록(서식 체크박스) 로드 안정 대기 → [전체선택] 클릭
  → 일괄출력 클릭 사다리(최대 4회) — confirm 자동승인 쿠키(savetax_batch_ok)로 발동 검증
  → 이후 240초 팝업 내부 감시(batch-diag: 레이어/iframe 중계)
  [background print-pdf]
  → 탭 전체 프레임 프로브(allFrames:true) — m_pageCount + 페이저 '전체 페이지' input 판독
  → 병합 도착 = 총페이지가 baseline보다 "증가"(grown) && 3연속 안정 → 캡처 확정
    (증가 없으면 마지막페이지 버튼 강제 클릭으로 렌더 유도, 그래도 불변이면 60초 fullyStable,
     최후 220초 overdue 폴백)
  → 디버거 Fetch 인터셉트 + directPDFPrint() 호출(서버 전체분 PDF) → 12초 내 미도착 시 pdfDownLoad() 폴백
  → PDF 응답 가로채고 Abort(로컬 다운로드 차단) → 앱 업로드 → 캡처 PDF 페이지 수(pdfPages) 자가검증
→ close-report-tab(UTERNAAZ34/39·sesw 잔여 탭 정리) → 다음 행/연도 반복
→ 전 구간 종료 후 mark-collected(collected/empty) — 조회를 한 번도 못 했으면 상태 미갱신(throw)
```

## 2. 피 흘리며 확정한 함정들 (전부 실측)

1. **일괄출력은 "신고서 목록 체크박스에 체크된 서식"만 병합한다.** 팝업이 뜨자마자 누르면 목록이
   로드되기 전이라 본표만 병합돼 1쪽 PDF가 나온다(v4.10~4.19의 근본 원인). 반드시 체크박스 로드
   안정 대기 → [전체선택] 클릭 → 일괄출력 순서. 추계신고가 멀쩡해 보였던 건 본표=전체(3쪽)라서
   생긴 우연 — "일부 세목만 성공"은 이 함정을 의심할 것.
2. **m_pageCount는 총페이지가 아니라 "지금까지 생성된 페이지 수"다**(ClipReport 지연 생성).
   총페이지의 권위 판독원은 뷰어 페이저의 `input[title='전체 페이지']`(value "/ 9").
3. **pdfDownLoad()는 클라이언트에 생성된 페이지만 내보낸다.** 서버 전체분은 `directPDFPrint()`가
   가져온다(v4.19). 인쇄 미리보기(printWindowView)가 전체 쪽수를 보여주면 서버에 전체분이 있다는 뜻.
4. **합성 클릭은 "성공 로그"를 믿으면 안 된다** — 클릭 발동은 confirm 자동승인 시 심는
   `savetax_batch_ok` 쿠키(suppress-alert)로 검증한다. 검증 실패 시 클릭 사다리(content 포인터+좌표
   이벤트 ↔ MAIN world native click + WebSquare API)로 재시도.
5. **뷰어는 sesw.hometax.go.kr 교차출처 iframe**(src는 about:blank — POST 로드, 데이터는 Clip.jsp XHR).
   페이지네이션 DOM 텍스트 파싱·인쇄 버튼 합성 클릭 경유는 실패(폐기). 프레임 추적은
   viewer-frame-ready(인쇄 버튼이 "보이는" 프레임만 보고됨) + 캡처 후보는 allFrames:true 전체 프로브.
6. **죽은 frameId가 쌓인다** — 뷰어 프레임은 수집 중 여러 번 교체되므로 캡처 후보는 keys>0
   살아있는 프레임만. 리포트 객체의 무인자 함수 직접 호출 금지(removePageMoveButton 사고) —
   UI 버튼 click()만 허용.
7. **window.open 팝업은 부모 sessionStorage(savetax_creds)를 복사 상속** → 팝업 안에서 수집모드가
   재실행되는 사고. 모든 최상위 IIFE에 `window !== top` 가드 + 수집 IIFE에 popup.html 가드 필수.
8. **느린 네트워크에서 세목 select 옵션이 늦게 채워진다** — 옵션 없이 조회하면 전 구간 0건.
   0건 결과를 앱에 empty로 보내면 "화면 로드 실패"가 "내역 없음"으로 둔갑하므로, 세목 선택 실패나
   조회 0회 실행 시엔 mark-collected를 호출하지 않고 throw(재시도 가능 상태 유지).
9. **조회 후 "대상이 보이면 즉시 진행" 폴링은 직전 연도의 잔존 그리드를 오인한다**(2025 조회에
   2024 행이 잡힌 사고). 조회 전 그리드 서명을 찍고 "달라질 때까지" 대기.
10. suppress-alert.js는 자동클릭 로직 때문에 all_frames 금지. confirm("소요됩니다"/"계속 진행")
    자동 승인 + savetax_batch_ok 쿠키는 이 파일이 담당.

## 3. 다른 세목으로 확장하는 법

세목 연결은 이미 되어 있다 — `content-hometax.js`의 RT 매핑(returnType → 세목 텍스트/docKey):
income(종합소득세)·vat(부가가치세)·corp(법인세)·transfer(양도소득세)·gift(증여세).
`DataCollectBoard.tsx`의 build 함수들도 세목별로 존재. 즉 **새 코드가 아니라 실측 검증이 남은 상태.**

세목별 확인 체크리스트:
- [ ] 전자신고결과조회 화면에서 해당 세목 select 옵션 텍스트가 RT.tax와 부분일치하는지
- [ ] 등록번호: 부가세/법인은 사업자번호 우선, 종소/양도/증여는 주민번호 우선(이미 분기됨) —
      거래처에 해당 번호가 등록돼 있는지
- [ ] 접수번호 링크 형태가 `/^\d[\d-]{5,}/` 패턴에 걸리는지 (마스킹 '*' 포함 링크는 제외됨)
- [ ] 신고서보기 팝업이 UTERNAAZ34인지(다른 화면ID면 팝업 스크립트 가드 URL 추가 필요)
- [ ] 신고서 목록 체크박스/[전체선택]/일괄출력 버튼(mf_triMatePrint)이 같은 구조인지
- [ ] `lib/doc-types.ts` 기본 기간이 과거 이력 수집 용도에 맞는지 (종소세는 2020-01-01 시작으로
      고정했음 — 다른 신고서도 같은 정책으로 바꿀지 결정)
- [ ] 1건 수집해서 [캡처디버그]의 forms/base/total/pdfPages 확인

## 4. 캡처디버그 읽는 법 (실패 시 첫 번째로 볼 것)

메인 창 콘솔 `SaveTax: [캡처디버그] {...}`:
- `click:{a,v,m,forms:{n,c}}` — 일괄출력 클릭 시도 수/발동 검증 여부/방법, 신고서 목록 개수(n)와 체크 수(c)
  → v:false면 클릭 문제, n=0이면 목록 로드 문제, c<n이면 전체선택 실패
- `base` → `total` — 일괄출력 후 첫 관측 총페이지 → 캡처 시점 총페이지. base==total(증가 없음)이면
  병합이 안 걸린 것(함정 1번 의심)
- `sec` — 클릭 후 캡처까지 초. 60초대=fullyStable, 220초대=overdue 폴백(병합 미도착)
- `lp` — 마지막페이지 강제 클릭 횟수
- `pdfPages` — 캡처된 PDF의 실제 페이지 수(추정). total과 다르면 추출 경로 문제(함정 3번)
- `method` — clipreport-directPDFPrint(정상) / clipreport-pdfDownLoad(폴백) / print-to-pdf(구 경로)
- `probes[].u/t/c` — 프레임별 URL/총페이지/속성 덤프, `diag` — 팝업 내부 레이어/iframe 스냅샷
- `tabs` — 캡처 시점 열려 있던 리포트류 탭
